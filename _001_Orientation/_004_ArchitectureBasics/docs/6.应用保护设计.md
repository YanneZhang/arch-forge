# <span style="color:rgb(0, 112, 192)">1 概述</span>
1. 优先保证核心业务
2. 优先保证绝大部分用户
3. 降级、熔断、限流、
# <span style="color:rgb(0, 112, 192)">2 降级</span> 
1. 100个功能，降低到50个功能，减少部分功能或所有功能
2. 系统后门接口，位，切面（写注解，做切面，切前做判断）风险是被黑客发现了，就会被恶意调用
3. 独立的降级系统，后台降级系统，做界面化封装
4. 自动降级
	1. 时机（超时、失败次数、故障、限流）
	2. 如何做（停止读取数据库、用静态结果、同步转异步、功能裁剪、禁止写操作、分用户降级、工作量正铭降级POW）
# <span style="color:rgb(0, 112, 192)">3 熔断</span> 
1. 降级是系统内部执行一些操作，控制系统内的接口是否可用
2. 熔断是调用外部接口，当某个接口错误率太高，超过阈值，或超时很长，则不再调用某个接口
3. 熔断策略：请求失败率、响应时间、
4. 熔断和降级的区别：熔断是调用方处理，降级是本服务自身
# <span style="color:rgb(0, 112, 192)">4 限流</span>
1. 降级从系统功能角度，优先保证哪些功能可用
2. 限流是限定
3. 秒杀场景
4. 基于请求，从外部请求访问，限制总量，单位时间的阈值
5. 基于资源
